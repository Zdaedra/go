# ТЗ: мобильное приложение «Дебюты Го 9×9»

Версия 1.0 — черновик для MVP. Язык интерфейса: русский (i18n-каркас с
самого начала, en — второй локалью).

## 1. Идея

Простое мобильное приложение-тренажёр дебютов на доске 9×9. Пользователь
расставляет камни на гобане — приложение в реальном времени опознаёт, в
какой **дебют** и в какую **ветку** он входит, называет их, показывает
оценку варианта (=, B+, W+) и подсказывает пункты продолжений (буквы
A, B, C… и треугольники) ровно там, где они стоят в базе.

Источник данных — уже готовая база в этом репозитории:

- `data/openings/9x9/openings.json` — 46 дебютов, 259 диаграмм, 1718 ходов,
  продолжения с точными координатами и кросс-ссылками.
- `data/openings/9x9/branches.json` — пронумерованные ветки каждого дебюта
  (`family/opening/N`), восстановленные полные линии от пустой доски
  (141 шт.) и **индекс позиций**: 1614 канонических позиций → ветка/ход.
  Именно этим индексом приложение опознаёт дебют за O(1) на каждый ход.

## 2. Платформа и стек

- **Клиент**: React Native + Expo (iOS + Android из одной кодовой базы).
  Доска — SVG (react-native-svg); референс отрисовки и логики уже есть в
  `data/openings/9x9/viewer.html` (тот же JSON, камни, буквы, треугольники,
  снятие камней) — переносится в компоненты почти один в один.
- **Оффлайн-first**: обе JSON-базы кладутся в бандл приложения (~1 МБ).
  Опознавание дебютов работает без сети. Сеть нужна только для
  регистрации, подписки и синхронизации прогресса.
- **Бэкенд**: минимальный FastAPI-сервис на существующем сервере Hetzner
  (рядом с текущими сервисами репозитория): auth по email (magic link /
  код), учёт дневного лимита, вебхуки платёжного провайдера, прогресс
  пользователя. Postgres или SQLite — нагрузки минимальные.
- **Платежи**: подписка $5/мес через нативные механизмы (StoreKit /
  Google Play Billing), обвязка — RevenueCat, чтобы не писать свою
  серверную валидацию чеков.

## 2.1 Режимы приложения

Два режима, переключаются табами внизу:

1. **Режим игры («лайв»)** — главный режим, доска с живым опознаванием
   (§3.2 и §4): ставишь камни, приложение определяет дебют и ветку,
   показывает варианты и буквы продолжений.
2. **Режим обучения** — по требованию: **просто список дебютов, текстом.**
   Плоский список по семействам (тэнгэн, хоси, такамоку, территориальные):
   название, сложность ★–★★★, число веток, результат основных веток.
   Тап по названию открывает карточку дебюта (§3.3), откуда линию можно
   проиграть на доске. Никакого отдельного «пошагового урока» в MVP нет —
   обучение = список + карточки + проигрывание веток.

**Названия дебютов**: в MVP сохраняем авторские названия из базы как есть
(Curveball, Black Boomerang, …). Названия вынесены в один словарь
(`src/data/names.ts`), чтобы позже переименовать/локализовать одним файлом.

## 2.2 Внешний вид доски и камней

- Доска и камни должны быть **красивыми**: дерево с текстурой, камни
  с объёмом (блик/тень), аккуратные линии и хоси.
- **Темы доски и темы камней выбираются независимо** в настройках:
  реестры `boardThemes` и `stoneThemes` в коде, каждая тема — набор
  параметров отрисовки (градиенты/цвета/текстура).
- Отрисовка — SVG (react-native-svg), без бинарных ассетов; за референс
  берём открытые темы гобанов (Sabaki, Lizzie, online-go — все open
  source) и уже готовый рендер из `data/openings/9x9/viewer.html`.
- Минимум тем в MVP: доска — «кайя» (классическое дерево), «тёмная»,
  «бумага»; камни — «сланец и ракушка» (объёмные), «матовые», «плоские».

## 3. Экраны

### 3.1 Онбординг и регистрация
1. Приветствие: 2–3 слайда «что умеет приложение» (доска, опознавание,
   ветки).
2. Регистрация **только по email**: пользователь вводит почту → получает
   6-значный код (или magic link) → вход. Без паролей.
3. После входа сразу открывается Доска.

### 3.2 Доска — режим игры / «лайв» (главный экран)
- Гобан 9×9 (дерево/тёмная тема), координаты A–J / 9–1.
- Сверху переключатель: **«Я играю за: ⚫ / ⚪»** (по умолчанию чёрные).
- Пользователь ставит камни по очереди за обе стороны (ходы строго
  чередуются, взятия снимаются по правилам).
- Панель статуса под доской — главный элемент механики (см. §4).
- Кнопки: ход назад, сбросить доску, «показать варианты» (вкл/выкл
  подсказки), меню.

### 3.3 Карточка дебюта
Открывается тапом по названию опознанного дебюта:
- название, семейство (тэнгэн/хоси/такамоку/территориальные), сложность
  (★–★★★), число веток;
- список веток: «ветка 1», «ветка 2», … с подписью и результатом (=/B+/W+);
- тап по ветке — автопроигрывание линии на доске (слайдер как во
  viewer.html).

### 3.4 Пейволл
- Появляется, когда исчерпан дневной лимит бесплатного тарифа.
- Текст объясняет ценность: «Полная база: 46 дебютов, 259 вариантов с
  названиями веток и подсказками продолжений. Бесплатно — опознавание
  3 дебютов в день. Подписка $5/мес — без ограничений».
- Кнопки: «Оформить $5/мес», «Восстановить покупку», «Напомнить завтра».

### 3.5 Профиль/настройки
- email, статус подписки, тема (светлая/тёмная/системная), язык,
  выход из аккаунта, удаление аккаунта (требование сторов).

## 4. Основная механика (панель статуса)

Состояния панели после каждого поставленного камня:

1. **Позиция найдена, дебют ещё не определён однозначно**
   (несколько кандидатов): «Возможные дебюты: Curveball, Hand Fan,
   Orthodox…» + **три варианта** следующего хода из базы — полупрозрачные
   метки прямо на доске (приоритет: продолжения, ведущие в самые
   популярные/ранние ветки).
2. **Дебют определён однозначно** (остался один кандидат): панель
   объявляет: «Дебют: Curveball ★★, ветка 1» — с этого момента название
   закреплено и обновляется только номер ветки по мере углубления.
3. **Достигнута финальная позиция диаграммы**: на доске появляются
   **буквы A, B, C… и треугольники на своих координатах** (поле
   `continuations` в базе). Тап по букве: если у неё есть `next` —
   переходим в следующую диаграмму-ветку (камень ставится сам, панель
   называет новую ветку); если `next` нет — просто ставится камень-кандидат.
4. **Такого дебюта нет**: позиция не найдена в индексе — панель говорит
   «Такого дебюта в базе нет» + кнопка «вернуть ход». Камень остаётся:
   пользователь волен играть дальше, опознавание возобновится, если
   позиция снова совпадёт с базой (транспозиция).

Алгоритм опознавания (уже проверен на данных):
- после каждого хода позиция доски канонизируется по 8 симметриям
  (минимальная строка из 81 символа) и ищется в `position_index`;
- совпадения дают список (ветка, ход, ориентация); подсказки и буквы
  переводятся в ориентацию доски пользователя обратным преобразованием
  (`inverse_transforms` в branches.json);
- «за кого я играю» влияет только на то, чьи варианты подсвечиваются
  подсказками (поле `by` у продолжений) — ставить камни можно за обе
  стороны.

## 5. Freemium-логика

- **Бесплатно**: 3 опознанных дебюта в день. Считается по событию
  «дебют определён однозначно» (состояние 2 в §4) для *разных* дебютов;
  повтор того же дебюта в тот же день не тратит лимит.
- Счётчик хранится локально и на сервере (сброс в 00:00 локального
  времени); при выходе из аккаунта лимит не обнуляется.
- **Подписка $5/мес**: безлимит. Кэшируется оффлайн (grace period 7 дней
  без сети).
- Карточки дебютов сверх лимита показываются в «замке» с CTA на пейволл.

## 6. Бэкенд API (минимум)

```
POST /auth/request-code     {email}            -> 200 (письмо с кодом)
POST /auth/verify           {email, code}      -> {jwt}
GET  /me                                        -> {email, plan, daily_used}
POST /usage/opening-identified {opening_id}    -> {daily_used, limit}
POST /billing/webhook       (RevenueCat)       -> обновляет plan
GET  /progress | PUT /progress                  -> изученные ветки (JSON)
```

Всё остальное — на клиенте. Базы дебютов сервер не раздаёт (они в бандле);
обновления базы приходят с обновлением приложения.

## 7. Существующие наработки (сервер Hetzner / этот репозиторий)

Что переиспользуем и что сознательно не тащим в мобильную версию —
см. отчёт в §7.1.

### 7.1 Ревизия активов (по результатам обзора репозитория)

**Берём:**
- **`data/openings/9x9/` + `scripts/`** — ядро приложения, готово.
- **`data/openings/9x9/viewer.html`** — референс UI: камни, буквы,
  треугольники, слайдер, взятия — портировать в RN-компоненты.
- **`apps/lesson-player/frontend/components/GoBoard.tsx`** — лучшая база
  для доски: лёгкий **SVG**-гобан на GTP-координатах (A–J/1–9), совпадающих
  с форматом `openings.json`; умеет ghost-камни для подсказок вариантов
  (`variationSequence`, `marks`). Без картинок-ассетов — чисто переносится
  в react-native-svg.
- **`apps/orchestrator/routers/auth.py` + `security.py`** — рабочий
  FastAPI-auth (register/login/forgot/reset, bcrypt + JWT на 7 дней) —
  основа мини-бэкенда §6; добавить вход по коду из письма.
- **`apps/orchestrator/game_manager.py`** (строки ~21–94) — чистый движок
  взятий (группы, либерти, самоубийство) — серверная валидация при
  необходимости; на клиенте та же логика уже есть в viewer.html.
- **`@sabaki/go-board`** (используется в lesson-player) — готовая npm-
  библиотека состояния доски/SGF для клиента.

**Не тащим в мобильную версию:**
- `online_go/components/GoBoard.tsx` — тяжёлая DOM-доска на PNG-ассетах,
  framer-motion и Tailwind; web-only. Auth-страницы `online_go/pages/*`
  годятся лишь как референс UX.
- `apps/katago-engine-service` — движок не нужен для MVP (v2 — возможно).
- `apps/crawler-worker`, `apps/go-worker`, `go-mechanics-bot/`,
  `apps/dashboard` — краулеры/скрейпинг OGS/админка, к приложению
  отношения не имеют.

**Придётся писать с нуля:** платежи/подписка — в репозитории кода оплат
нет вообще; берём RevenueCat + вебхук в оркестраторе (поле `plan` у
`models.User`).

## 8. Этапы

1. **MVP (3–4 недели)**: доска + опознавание + карточки дебютов +
   регистрация email + лимит 3/день + пейволл с подпиской.
2. **v1.1**: прогресс «изученных» веток, автопроигрывание линий, поиск.
3. **v2**: режим тренировки (приложение играет за соперника по веткам
   базы), оценка отклонений через KataGo-сервис, 19×19.

## 9. Не входит в MVP

- Игра с движком, задачи/цумэго, мультиплеер, push-уведомления,
  социальные функции, веб-версия (есть viewer.html для отладки базы).
