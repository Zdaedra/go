# ТЗ: Интернационализация (i18n) v1

**Дата:** 2026-07-11 · **Продукт:** `apps/mobile` (RN/Expo) · **Статус:** в работе

## Цель

Всё, что написано словами в приложении, существует на 6 языках: **ru, en, es, fr, de, ko**.
Ни одна фраза не «висит в дизайне» — каждая имеет каноническую запись в каталоге с уникальным
ключом и переводом на все локали.

## Локали и выбор языка

- Поддерживаемые: `ru en es fr de ko`. Язык интерфейса по умолчанию — **язык устройства**,
  если он в списке; иначе **en**.
- В настройках (Профиль → Настройки) — переключатель: «Авто (язык устройства)» + 6 языков.
  Выбор персистится (AsyncStorage `lang.v1`), «Авто» = следовать устройству.
- Детект языка — без нативных модулей (`NativeModules.SettingsManager` / `I18nManager`),
  уже реализовано в `src/i18n/index.tsx`.

## Каталог фраз = база данных

- **Источник правды:** `apps/mobile/src/i18n/strings.json` — `{ key: { ru, en, es, fr, de, ko } }`.
  Версионируется git'ом; каждая правка фразы — коммит с прогоном аудита. Это и есть БД фраз v1:
  однозначный маппинг «ключ → перевод на каждую локаль».
- **Правило:** в JSX/TS не бывает пользовательских строк-литералов — только `t('key')`.
  Исключения: числа, символы (△, •, ✦), имена собственные, которые не переводятся.
- **v2 (отложено):** экспорт каталога в БД бэкенда kai (endpoint), когда фразы понадобятся
  серверу (письма, веб). Формат уже совместим: key → locale → text.

## Слои контента

| Слой | Что | Где | Политика |
|---|---|---|---|
| A | UI-строки (кнопки, заголовки, плашки, настройки) | `strings.json` | 100% на всех 6 локалях, всегда |
| B | Контентные имена: 44 названия дебютов, 4 семьи, 6 доменов, разделы каталога | `src/data/names.ts` → локале-словарь | 100% на всех 6; названия дебютов — оригинальные образы (см. ниже) |
| C | Длинные тексты: описания веток (`descriptions.json`), hint-тексты задач | отдельные словари | волнами; ru+en в v1, остальное по проценту |

**Названия дебютов (слой B):** русские имена — оригинальные (сгенерированы 2026-07-10,
книжные английские имена — явный блоклист, авторские права). Переводы на en/es/fr/de/ko
делаются от НАШИХ образов («Ковш» → Ladle/Cazo/…), с обязательной проверкой: перевод en
не должен совпасть ни с одним книжным именем из базы (`opening_name`).

## Процент покрытия — обязательный ритуал

- `apps/mobile/scripts/i18n_audit.mjs`:
  1) для каждой локали — % ключей с непустым переводом (по слоям A/B/C и суммарно);
  2) детект кириллицы вне словарей (`src/**` кроме `i18n/strings.json`, `data/names*`,
     комментарии игнорируются) — новый хардкод = ошибка;
  3) ненулевой exit code при хардкоде или падении покрытия — готов для CI.
- **Любое изменение строк сопровождается прогоном аудита; проценты — в отчёте/коммите.**

## Пайплайн перевода

1. Инвентаризация: хардкод из экранов → ключи + ru-текст (слой A), имена → слой B.
2. Перевод на en/es/fr/de/ko — Claude (внутри сессии), с Go-терминологией:
   ko/атари/цумэго/сэки — устоявшиеся термины каждой локали (ko: 패/단수/사활).
3. QA: полный словарь одним батчем → ChatGPT (через Chrome, не API) — вычитка
   естественности, терминов, длины строк; правки → каталог.
4. Симулятор: смена языка в настройках, скриншоты ключевых экранов (минимум ko + es):
   переполнения, обрезки, нечитаемые шрифты.

## Definition of Done v1

1. `LANGS = [ru, en, es, fr, de, ko]`, переключатель в настройках со всеми шестью.
2. Автодетект языка устройства; не поддерживается → en.
3. Слои A и B: 100% ключей на всех 6 локалях, 0 хардкода (аудит зелёный).
4. Слой C: каталогизирован, % зафиксирован в аудите.
5. QA-проход ChatGPT выполнен, правки применены.
6. Скриншоты ko/es из симулятора без переполнений.
